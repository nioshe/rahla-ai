# Rahla.AI

A full-stack prototype for planning trips in Morocco. The project combines a responsive browser interface with a modular Node.js and Express API for trip plans, destinations, tours, appointments, and chat workflows.

## Project status

Rahla.AI is currently a portfolio prototype. Its API structure and request flows are implemented, while persistence and external AI-provider integration are not yet connected. Recommendation results are generated by deterministic application logic, and several service methods return mock data.

This distinction is intentional: the repository demonstrates application structure and API design without claiming a completed machine-learning system.

## Implemented

- Responsive single-page travel interface
- Express application with route, controller, and service layers
- Health-check endpoint
- Chat request and history endpoints
- Trip-plan creation, retrieval, update, deletion, and recommendation routes
- Tour and city endpoints
- Appointment booking and availability routes
- Budget-based trip-style, destination, hotel, tour, and itinerary recommendations
- Centralized 404 and error-handling middleware
- Environment-variable loading with `dotenv`

## Technology

- HTML5, CSS3, and browser JavaScript
- Node.js
- Express
- CORS
- dotenv

## Architecture

```text
.
├── index.html
├── package.json
└── server/
    ├── index.js
    ├── app.js
    ├── routes/
    ├── controllers/
    └── services/
```

Requests enter through the Express routes, are validated and coordinated by controllers, and delegate business behavior to service modules.

## Run locally

### Requirements

- Node.js
- npm

### Installation

```bash
npm install
```

Create `server/.env` only if local configuration is required. Environment files are ignored by Git and must not contain values intended for source control.

### Development

```bash
npm run dev
```

### Standard start

```bash
npm start
```

The server defaults to `http://localhost:5000`.

## Selected API routes

- `GET /health`
- `POST /api/chat/message`
- `GET /api/chat/history/:userId`
- `POST /api/planner/create`
- `POST /api/planner/recommend`
- `GET /api/planner/:planId`
- `GET /api/tours`
- `POST /api/tours/search`
- `GET /api/cities`
- `GET /api/cities/:cityId`
- `POST /api/appointments/book`
- `GET /api/appointments/:appointmentId`

## Current limitations

- No database persistence
- No external AI model or API integration
- Service data is mocked or generated in memory
- No authentication or authorization layer
- No automated tests; the current `npm test` script is a placeholder
- No production deployment configuration
